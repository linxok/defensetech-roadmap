# Лабораторна робота 17: підготовка відповідей

## Мета

Підготувати повний набір відповідей для співбесіди: технічні питання,
system design кейс і STAR-історії — з перевіркою повноти.

## Передумови

- Пройдені модулі 05–09 (профільний трек).
- Заповнений capstone, з якого беруться приклади.

## Кроки

1. Відкрийте `interview-questions.md` і `solution/answers-example.md`.
2. Створіть `answers.md` у своєму репозиторії.
3. Дайте відповіді на 10+ питань: суть → механізм → приклад з capstone
   → обмеження. Кожна відповідь — не коротша за 2–3 речення з числами.
4. Додайте один system design кейс (наприклад, телеметрія 1000 дронів).
5. Перевірте повноту:

```bash
python 17-interview/checks/check_lab.py --target 17-interview/solution
```

6. Проведіть дві мок-співбесіди по 30 хвилин і зафіксуйте фідбек.

## Очікуваний результат

- `answers.md` без заглушок, з конкретикою в кожній відповіді.
- Один розібраний system design кейс.
- Дві мок-співбесіди із списком зон росту.

## Перевірка

`checks/check_lab.py` вимагає 10+ розділів, відсутність
`_Ваша відповідь тут_`, мінімальну довжину відповідей і наявність
числової конкретики. Це формальний критерій, сенс — у моках.

## Розбір збоїв

- Відповіді вивчені напам’ять без прикладів — інтерв’юер це чує з
  першого питання; тренуйте переказ своїми словами.
- Немає чисел — «швидко» і «надійно» нічого не доводять.
- Ігнорування поведінкових питань — половина відмов стається саме там.
