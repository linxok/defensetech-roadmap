# 17. Підготовка до співбесіди

> Статус: outline

Підготувати відповіді на технічні та behavioral питання, зібрати system design кейси і провести мок-співбесіди.

## Що потрібно зрозуміти

- Інтерв’ю перевіряє три речі: чи розумієте механізми, чи вмієте їх застосовувати, чи можете про це говорити.
- Відповідь має структуру: суть → механізм → приклад з вашого проєкту → обмеження.
- System design кейси для флоту: телеметрія 1000 дронів, командний канал, зберігання логів, CV-обробка на edge.
- Behavioral питання за STAR; готуйте 5 історій, які закривають конфлікти, дедлайни, помилки, ініціативу.
- Питання до інтерв’юера: про процеси, тестування на залізі, code review — це теж сигнал вашої зрілості.
- Оцінка чесності: на незнайоме питання краще сказати «не працював, але ось як я б підійшов», ніж вигадувати.

## Контрольні питання

1. Як пояснити MAVLink людині, яка не в темі?
2. Скільки повідомлень/с витримає ваш gateway і як ви це знаєте?
3. Що станеться з вашим стеком при втраті одного вузла?
4. Яка найбільша помилка у вашому проєкті і що ви з неї взяли?
5. Які питання ви поставите інтерв’юеру?

## Очікуваний результат

Файл відповідей (еталон формату: `solution/answers-example.md`) + 2 мок-співбесіди.

## Зв'язок з capstone

## Типові помилки

- Відповідь без прикладу — виглядає завчено
- Ігнорування обмежень свого рішення
- Монолог на 10 хвилин замість діалогу
- Немає жодного питання до інтерв’юера
