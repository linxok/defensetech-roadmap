# Лабораторна робота 16: портфоліо-проєкт

## Мета

Упакувати навчальні артефакти в публічний репозиторій, який проходить
перевірку за бінарним Definition of Done.

## Передумови

- Виконаний capstone (або готовий його компонент).
- Git-акаунт із можливістю створювати публічні репозиторії.

## Кроки

1. Скопіюйте шаблон:

```bash
cp -r 16-projects/solution/starter-template ~/my-project
cd ~/my-project
```

2. Заповніть README: проблема, архітектура (mermaid), швидкий старт,
   метрики, обмеження. Кожен розділ — змістовний абзац (≥40 символів)
   без заглушок, а в README загалом мають бути числа; заглушки
   («Одне речення…», «Опишіть…») перевірка відхиляє.
3. Додайте тест, який падає на поганому вході, і зелений CI.
4. Перевірте шаблон (еталон, потім вашу копію):

```bash
python 16-projects/checks/check_lab.py --target 16-projects/solution
python 16-projects/checks/check_lab.py --target <тека з вашим starter-template>
```

5. Запишіть демо до 2 хвилин: запуск з чистого середовища і живий
   результат.
6. Опублікуйте репозиторій і додайте посилання в CV.

## Очікуваний результат

- Публічний репозиторій із README, тестами і CI.
- Виміряні метрики (p95, throughput, розмір даних).
- Відео-демо до 2 хвилин.

## Перевірка

`checks/check_lab.py` вимагає README з шістьма розділами, змістовний
абзац у кожному з них, відсутність заглушок, числа в тексті, CI з
pytest, піновані залежності й зелені тести шаблону. Порожня тека або
незаповнений README валять перевірку.

## Розбір збоїв

- CI «зелений», але тест нічого не перевіряє — додайте негативний кейс.
- Quickstart не працює з чистого середовища — перевіряйте в контейнері,
  а не у своєму venv.
- Секрети в історії git: навіть видалений файл лишається в історії,
  тому ключі — лише через змінні середовища.
